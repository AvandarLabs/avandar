# Theme coverage: follow-up token additions

Slices S3, S4, S7, and S8 asked for tokens the foundation did not add. This file maps each request to the token that answers it, or says why none was added. Every new token defaults to the literal it replaces, so `classic` draws the same pixels, and every one has a catalog entry. The [video theme guide](../video-theme.md) explains the tiers.

## How a slice picks up a token

- **Mantine and atomic tokens** are exempt from the reader audit. Read them as soon as this branch is merged.
- **Semantic tokens** that no renderer reads yet are listed in `handoffTokens` in `scripts/videoTheme/themeLiteralBudgets/s1.json`, each with the slices expected to read it. When a slice's renderer starts reading one, the reader audit fails until that slice deletes the token's entry from `s1.json`. This is the only edit a slice makes to another slice's budget.
- **Component tokens** (`Cursor.travelEasing`, `BrandLockup.flightPerspective`) already count as read, because the stage calls `useVideoProps("Cursor")` and `useVideoProps("BrandLockup")`.

## Guard follow-up

`stroke.heavy` and `dash.pending` are still listed in `s2.json` `pendingTokens`, but merged S3 and S4 renderers now read both. With them removed from `s2.json` and `enforceLint` turned on, the reader audit passes, so the guards need no change. Only the controller may make that edit to `s2.json`.
