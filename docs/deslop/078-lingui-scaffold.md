## What this feature is

The Lingui infrastructure that lets the codebase use `<Trans>` and the `t``` template-literal macro from `@lingui/react/macro`:

- `@lingui/*` packages installed.
- `lingui.config.ts` at repo root: 8 locales (`en, es, pt, fr, sw, ar, zh-Hans, zh-Hant`), source locale `en`, catalogs at `src/i18n/locales/{locale}/messages.po`.
- `vite.config.ts` updated so `@vitejs/plugin-react` runs the `@lingui/babel-plugin-lingui-macro` plugin.
- `src/i18n/` directory with the i18n setup module, locale registry, providers (App + Workspace), preference hook, and the 8 catalog directories (each containing `messages.po` + compiled `messages.ts`).
- `pnpm` scripts: `i18n:extract`, `i18n:compile` (and `i18n:translate-llm` if its script exists on the source branch).

## Risks + things to look out for

- **`pnpm install` may need lockfile regeneration.** The deps land in `package.json`; commit the updated lockfile.
- **`vite.config.ts` plugin order.** `reactWithLinguiMacro()` returns the `@vitejs/plugin-react` plugin with Babel additions. It must run before TanStack Router's plugin (Router needs to see the un-transformed JSX). Mirror the order on `feat/ict4d-demo`.
- **`tsconfig.json` may need the `@lingui/macro` types.** If `pnpm tsc` complains about missing types for the macro, add `"types": [..., "@lingui/macro"]` to `tsconfig.json`. Usually unnecessary because `@lingui/react/macro` re-exports the runtime values.
- **App entry placement of `<AppI18nProvider>`.** If the app already wraps with other providers (Mantine, TanStack Router, Auth), put `<AppI18nProvider>` **above** them so route-level components can use `<Trans>`.
