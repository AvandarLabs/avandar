# Skip CI/CD Workflows for `[skip deploy]` and Safe Documentation/Skill Changes

## Intent and Why

Version bump commits (`Release: vX.Y.Z [skip deploy]`, `Bump version to X.Y.Z-dev [skip deploy]`), documentation updates, and agent skill edits currently trigger full CI/CD runs across staging, production, package releases, PR checks, and React Doctor (60+ minutes of runner time per push). Skipping all workflows when every commit in a push or pull request opts out via `[skip deploy]` or only touches non-runtime documentation and agent-skill files avoids wasted CI time without reducing protection on runtime code, database migrations, or platform-rendered markdowns.

## Goals, Non-Goals, and Anti-Goals

### Goals

- Skip all automated CI/CD jobs on `push` to `main` and `develop` across `.github/workflows/production.yaml`, `.github/workflows/staging.yaml`, `.github/workflows/release-packages.yaml`, and `.github/workflows/react-doctor.yml` when **every** commit in the pushed range qualifies.
- Skip heavy PR checks on `pull_request` across `.github/workflows/pr-develop.yaml` (keeping `lint-pr-title` active) and `.github/workflows/react-doctor.yml` when **every** commit in the pull request (`base.sha..head.sha`) qualifies.
- Treat a commit as qualifying if **either**:
  1. Its commit subject (`%s`) contains `[skip deploy]`, **or**
  2. It changes at least one file and **every** changed entry matches the safe documentation / agent-skill file rules below.

### Safe Documentation and Agent-Skill File Rules

When a commit subject does not contain `[skip deploy]`, every changed entry in that commit (added, modified, deleted, or type-changed) must match one of:

1. A `.md` file under root `docs/` (`docs/**/*.md`).
2. A file or symlink named `AGENTS.md`, `CLAUDE.md`, or `README.md` at any depth.
3. A `.md` file under root `agent-skills/` or `.agents/`.
4. A `.md` file under `.claude/skills/`, `.cursor/skills/`, or `.opencode/skills/`.
5. A git symlink (mode `120000`) directly under `.agents/skills/`, `.claude/skills/`, `.cursor/skills/`, or `.opencode/skills/` (generated by `agent-skills/symlink-skills-dirs.sh`).

Non-markdown files inside `docs/`, `agent-skills/`, `.agents/`, `.claude/skills/`, `.cursor/skills/`, and `.opencode/skills/` (for example Rust, Python, JavaScript, TypeScript, shell scripts, or JSON eval data) do **not** qualify unless the commit subject includes `[skip deploy]`. Markdown files outside these rules (for example `plugins/mozambique/content/*.md` or `public/**/*.md`) do **not** qualify because they may be rendered by the platform.

### Non-Goals

- Do not modify `.github/workflows/claude.yml` (triggered only by explicit `@claude` mentions).
- Do not modify `lint-pr-title` in `.github/workflows/pr-develop.yaml` (Conventional Commit PR titles remain enforced on every PR to `develop`).
- Do not skip `workflow_dispatch` runs (manual runs always execute).
- Do not change Vercel's `[skip deploy]` handling or `apps/ava-cli` commit messages.

### Anti-Goals (Fail-Closed Safety)

- Never skip when the commit range cannot be resolved (all-zero `before` SHA on branch creation, unreachable `before` after a force-push, empty commit list, or git failure).
- Never skip an empty commit (`--allow-empty`) that does not say `[skip deploy]`.
- Never skip based on `[skip deploy]` appearing inside a commit body: GitHub squash merges copy individual PR commit subjects into the squash body, so inspecting only the commit subject (`%s`) prevents a historical `[skip deploy]` PR commit from skipping Staging CI or migrations on merge to `develop`.
- Never skip a merge commit (2+ parents) unless its own subject contains `[skip deploy]` or every file in its first-parent diff satisfies the safe file rules, ensuring production release merges (`Release X.Y.Z`) onto `main` always run CI/CD.
- Never break npm OIDC trusted publishing in `.github/workflows/release-packages.yaml`: the `release` job must remain directly inside `release-packages.yaml` rather than behind a reusable workflow so `job_workflow_ref` stays unchanged.

## Constraints

- Both the Develop and Main GitHub rulesets have no required status checks, so skipped downstream jobs will not block merges.
- The skip gate must run in a few seconds with zero `pnpm install`: pin `node-version: 24.15.0` via `actions/setup-node@v5` and execute zero-dependency TypeScript directly under Node 24's native type stripping (using explicit `.ts` relative imports, compatible with `tsconfig.base.json`'s `allowImportingTsExtensions: true`).
- TypeScript implementation and tests must live under `scripts/ci/` and follow `docs/rules/typescript.md` and `docs/rules/testing.md` (covered automatically by `pnpm type-check`, `pnpm lint`, and `pnpm test:frontend`).
- Checkout for the gate job must fetch full commit/tree history (`fetch-depth: 0`, `filter: blob:none`) so `git rev-list` and `git diff-tree --raw` can inspect pushes of any size (including >20 commits, where GitHub's webhook payload truncates `commits`).

## Approaches

| Approach | Description | Trade-offs |
| --- | --- | --- |
| **1. Shared tested TS script + local composite action (Picked)** | Pure TypeScript decision modules under `scripts/ci/should-skip-ci/` (tested with Vitest) executed by Node 24 from a local composite action `.github/actions/check-skip/action.yml`, wired into a ~5s `check-skip` gate job in each workflow. | Unit-testable, handles >20 commits and git symlink modes accurately, avoids duplicating git logic across 5 workflows, and keeps the `release` job directly in `release-packages.yaml` for npm OIDC. |
| **2. Inline shell gate job per workflow** | Embeds `git rev-list` and `case` path matching inline in each workflow YAML. | Zero extra directories, but duplicates subtle git range, merge, and symlink edge cases across 5 workflows with no unit tests. |
| **3. Native `paths-ignore` + expression `if:`** | Uses workflow-level `paths-ignore` plus `${{ github.event.commits }}` checks. | Cannot handle mixed `[skip deploy]` + markdown pushes per commit, caps at 20 commits in the webhook payload, and lacks an array-wide `every()` operator in GitHub expressions. |

**Why Approach 1 was picked:** It is the only approach that evaluates per-commit rules accurately across arbitrary push sizes, verifies symlink modes safely, keeps `release-packages.yaml` OIDC intact, and lets every edge case be locked down with fast Vitest unit tests.

## Decisions

### Decided by Pablo

- **Event and workflow scope:** Apply skip gating to `push` on `main` and `develop` (`production.yaml`, `staging.yaml`, `release-packages.yaml`, `react-doctor.yml`) **and** `pull_request` (`pr-develop.yaml` excluding `lint-pr-title`, plus `react-doctor.yml`), skipping only when every commit in the push or PR qualifies.
- **Safe file scope:** Include `.md` files under `docs/`, `agent-skills/`, `.agents/`, `.claude/skills/`, `.cursor/skills/`, and `.opencode/skills/`; files/symlinks named `AGENTS.md`, `CLAUDE.md`, or `README.md` at any depth; and skill directory symlinks under `.agents/skills/`, `.claude/skills/`, `.cursor/skills/`, and `.opencode/skills/`.
- **Architecture:** Approach 1 (shared tested TS script + local composite action gate job), starting with this short design spec and an implementation plan.

### Builder Calls (Confirm While Reading)

- Check `[skip deploy]` on commit subject (`%s`) only, never the body, to protect squash merges on `develop`.
- Treat `workflow_dispatch` as never skippable.
- Fail closed (run CI) on empty commit ranges, all-zero `before` SHAs, unreachable SHAs, empty commits without `[skip deploy]`, type-changed files where either old or new mode is unsafe, and git errors.
- Check merge commits via their subject or first-parent diff so `Release X.Y.Z` merges to `main` never skip.
- Use `fetch-depth: 0` with `filter: blob:none` in each workflow's `check-skip` checkout step (before calling the local composite action) so git inspects arbitrary commit counts quickly without downloading historical file blobs.
